# 代码审查与安全审计规范 (Code Review & Security Audit)

## 概述
本技能提供系统化、多维度的代码审查方法论，用于在代码合并、发布或重构前发现架构缺陷、安全隐患、性能瓶颈与异常处理盲区。

---

## 审查维度清单

### 1. 🛡️ 安全性检查 (Security & OWASP)
- **命令注入与路径穿越**：检查是否有未经校验的外部输入直接传给 `exec`, `spawn`, `eval` 或路径拼接。
- **凭据泄漏**：检查是否存在明文 Hardcoded 密码、私钥、API Key、连接字符串等。
- **权限与授权**：检查关键写操作是否有权限校验和防护。

### 2. ⚡ 健壮性与异常处理 (Robustness & Error Handling)
- **边界条件处理**：空指针、`null` / `undefined` 解构、空数组、超大输入等极端情况。
- **资源释放**：文件句柄、数据库连接、子进程监听器、定时器是否在 `finally` 块中妥善清理或注销。
- **优雅降级**：网络超时、第三方服务中断时是否有兜底重试与错误提示，避免整个应用崩溃。

### 3. 🎯 类型与架构设计 (Type Safety & Architecture)
- **类型严谨性**：避免滥用 `any`，确保关键接口、返回值具备精确的类型契约。
- **模块职责边界**：单一职责原则，避免在一个文件或类中混合过多元数据与副作用。

## 审查报告输出标准格式

输出代码审查意见时，采用如下结构化 Markdown：

```markdown
### 📋 审查总结
- **总体结论**：[通过 / 需修复后通过 / 存在阻断性缺陷]
- **发现问题总数**：高危 (X) | 中危 (Y) | 优化建议 (Z)

### 🚨 严重问题 (Blockers)
1. **[文件路径:行号] 问题简述**
   - **原因分析**：...
   - **改进建议 / 修复代码**：...

### 💡 改进建议 (Improvements)
- [建议 1]
- [建议 2]
```
